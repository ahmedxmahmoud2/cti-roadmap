## في الشغل

بعد أي report مهم، بتدّي فريق الـ hunting hypotheses مبنية على الـ TTPs، وساعات بتكتب الـ Sigma rule بنفسك. الجزء المفيد هو الـ feedback: إيه اللي اشتغل، وإيه اللي طلع noise، وده بيقولك إيه عن الـ threat.

## محتاج تعرف إيه

### منهجية الـ Threat hunting

الـ hunting المبني على hypothesis، وعلى IOCs، وعلى TTPs، وعلى السلوك، وعلى الـ anomalies، والـ threat-informed defense.

### الـ Detection engineering

الـ Sigma والـ YARA والـ Suricata rules. ولغات الـ query: KQL وSPL وEQL وCrowdStrike FQL.

### تحليل الـ Logs

- **Windows:** الـ Sysmon، والـ security logs، والـ PowerShell logs، والـ Defender logs، والـ process creation، وأحداث الـ authentication.
- **Network:** الـ DNS والـ proxy والـ firewall والـ Zeek logs، والـ Suricata alerts، والـ NetFlow.

### المنصات

Wazuh وSecurity Onion وSplunk وMicrosoft Sentinel وCrowdStrike Falcon وElastic Security.

## المشروع: من report لـ hunt

خد threat report واحد وحوّله لتلات hunting hypotheses. مثال: *الخصم ممكن يستخدم PowerShell عشان ينفذ commands متشفرة ويعمل persistence.* لكل واحدة، حدد الـ log source اللي محتاجها، واكتب query بسيطة أو Sigma rule. واكتبها كأنك هتسلّمها لفريق SOC.

## تقدر تنقل للخطوة الجاية لما

- تقدر تحوّل الـ TTPs اللي في report لـ hypotheses فريق الـ hunting يقدر يستخدمها.
- تقدر تقرا Sigma rule وتشرح هي بتكتشف إيه وممكن تعمل noise فين.
