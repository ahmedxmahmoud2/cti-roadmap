## On the job

After a relevant report, you give the hunting team TTP-based hypotheses, and sometimes write the Sigma rule yourself. The useful part is the feedback loop: what fired, what was noise, and what that tells you about the threat.

## What you will learn

### Threat hunting methodology

Hypothesis-based, IOC-based, TTP-based, behavioural and anomaly-based hunting, and threat-informed defense.

### Detection engineering

Sigma, YARA and Suricata rules. Query languages: KQL, SPL, EQL and CrowdStrike FQL.

### Log analysis

- **Windows:** Sysmon, security logs, PowerShell logs, Defender logs, process creation, authentication events.
- **Network:** DNS, proxy, firewall and Zeek logs, Suricata alerts, NetFlow.

### Platforms

Wazuh, Security Onion, Splunk, Microsoft Sentinel, CrowdStrike Falcon, Elastic Security.

## Project: hunting package

Pick an APT group and derive five hunting hypotheses from its TTPs. Example: *the adversary may use PowerShell to execute encoded commands and establish persistence.*

For each hypothesis:

- Define the required telemetry and data sources.
- Write the hunting query.
- Test it on lab logs and analyse the results.
- Identify false positives.
- Write the detection logic.
- Map it to ATT&CK.

Do not stop at "this APT uses PowerShell". You must be able to detect it.

## You are ready to move on when

- You can turn an actor's TTPs into hypotheses, queries and Sigma rules.
- You can explain the false positives your rules will produce.
